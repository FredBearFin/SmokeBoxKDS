# Smokebox KDS v2: design notes (shell / design-system layer)

Owner: shell. Files: `src/css/00-tokens.css`, `src/css/10-base.css`, `src/js/05-icons.js`, `src/js/60-shell.js`, `src/js/99-boot.js`.
Written before the code; the "Review" section records what the review changed. The contrast table at the bottom is generated by `node test/shell.contrast.mjs --write` from the live tokens.

## 1. Brief in one paragraph

A kitchen display for a BBQ joint, read in one-second glances by someone with greasy gloves under a skylight or in a dim prep corner. The palette is fixed by the brief (parchment, charcoal, zinc, brisket amber, sage, overdue crimson, white card, sub-surface). The product has two worlds: the bright, anti-glare **floor** and the dark **back office**, opened by a visible Back office button in the header (the five flame taps and Ctrl+Shift+O still work) and ignited out of the button or the flame. The memorable objects are the **ticket slip** and the **ignition**. Everything else is disciplined, flat, and quiet.

## 2. Plan (first pass)

### 2.1 Colour (core base palette, floor Day)

| Role | Name | Hex | Use |
|---|---|---|---|
| bg | Parchment | `#F5F2EB` | the board, the page under everything |
| ink | Charcoal | `#1E2224` | text, button edges, focus ring |
| line | Zinc | `#656E72` | 2 px structure: field borders, panel edges (never small text on `--sub`) |
| primary | Brisket Amber | `#B85C38` | fills, borders, large glyphs; white text on it is 4.54:1 |
| ok | Sage | `#5F7466` | done / success fills; white text 5.03:1 |
| bad | Overdue | `#9B2C2C` | overdue, destructive, the RUSH stamp |
| paper | Card | `#FFFFFF` | slips and field backgrounds |
| sub | Sub | `#EFECE6` | sheet headers, wells, segmented tracks |
| small-text inks | Amber ink `#A05031`, Sage ink `#576B5E`, ink2 `#3B4346`, ink3 `#566064` | | any text under 24 px that is not charcoal |

Night is the same system rotated: ground `#15181A`, bone ink `#EDE8DC`, light amber ink `#E8936B`, light sage ink `#93B49F`, light crimson `#E27B73`. **The slip stays paper in Night** (a dimmed bone `#E6E1D4`), because the slip is the object people recognise; a dark card would make the board a generic dark dashboard.

Office **Ember** is a different, warmer dark (not the floor's cool charcoal): ground `#181513`, bone `#EEE6D6`, ember `#E8743B`, sage `#8DB59B`, crimson `#E8776E`. Office **Paper** is its light twin. Both are exposed as `--o-*` and also re-mapped onto the floor token names inside `.office`, so every base component (buttons, sheets, fields) works unchanged in the office.

### 2.2 Type

* **Barlow Condensed** (display): ticket numbers 34, timers 30, headings, stamps, keypad digits. Heavy (700/800) because it is read at arm's length. Tabular figures wherever a number changes.
* **Barlow** (body): 17 px base on the floor, 15 secondary, 13 only for timestamps in `--ink3`. Scale fixed by spec: 13 / 15 / 17 / 20 / 24 / 32 / 44 / 64; item text 19.
* No monospace anywhere. No uppercase labels except stamps (RUSH, 86, OVERDUE-style status).
* Fallbacks look intentional if Google Fonts never load: `"Arial Narrow" / "Roboto Condensed" / "DejaVu Sans Condensed"` for display, `system-ui` for body.
* Line length: sheet copy is capped at 62ch.

### 2.3 Layout concept (shell level)

One fixed viewport, two stacked layers (floor, office), a sheet host above both, a toast host above that. Layers own their own scrolling. Sheets: right-hand panel on wide screens, full screen under 640 px. Toasts: bottom centre.

```

 +----------------------------+           +----------------------------+
 | header (floor owner)       |           |  back office frame         |
 | slips ...                  |   sheet   |  (office owner)            |
 |                            |  +------+ |                            |
 |        [ toast + undo ]    |  |panel | |                            |
 +----------------------------+  +------+ +----------------------------+
```

### 2.4 Principles

1. **Tactile, not glossy.** Pressables are flat slabs with a hard 3 px under-edge that closes when pressed (the original's charcoal-bordered, translate-on-press buttons, made consistent). No blur shadows on controls, no gradients except the clip metal and the smoke.
2. **Different roles, different corners.** Slips 2, chips 4, fields 6, buttons 8, dialogs 10, side sheets 0 on the leading edge.
3. **Structure is information.** A 2 px zinc edge means "interactive or container you can act on"; 1 px soft lines are only dividers. Perforation means "header above, work below".
4. **Never colour alone.** Status = word + icon + colour. Station = icon + 3-letter code + hue.
5. **Motion answers a touch.** Sheets slide from the edge they belong to, the toast rises from where it will be read, the stamp thumps in when RUSH is set. Nothing animates on load or scroll. The ignition is the single big non-functional moment.
6. **Quiet words.** Sentence case, plain verbs, no eyebrows, no middots, no arrow suffixes, no all-caps labels.

## 3. Review against the brief and against the generic defaults

I worked a similar prompt ("BBQ kitchen display, parchment and terracotta") in my head to see where a default would land: cream page, serif display, terracotta accent, rounded white cards with soft shadows, uppercase eyebrow labels, dark mode as a near-black with a lime accent. The brief pins the palette (parchment/terracotta is *its* choice, not mine), so the question is what I do on the free axes. Findings and revisions:

| First pass | Problem | Revision |
|---|---|---|
| Buttons: 12 px radius, soft drop shadow | the SaaS-card kit | flat slabs, 8 px, hard under-edge in the button's own edge colour, charcoal edge on Day (the original's look) |
| Night slip as a dark card | loses the object; looks like every dark dashboard | slip stays paper, dimmed to `#E6E1D4`; only the board goes dark |
| Ember office with orange glow gradients on cards | decoration, and it competes with the ignition | flat warm charcoal, ember only on accent, focus and the ignition; thin lines |
| RUSH as a filled pill | generic badge | rubber stamp: double ring, rotation, worn-ink mask, one 150 ms thump when it appears |
| Toast as a white card | disappears on parchment | inverse strip (charcoal in Day) with the drain bar flush on its bottom edge; undo is the only button |
| Ignition ring as a glow blob | not tied to the reveal | ring is the reveal edge: same radius, same easing as the `clip-path` circle; thin white-hot core, wide ember falloff |
| Station tabs/chips with uppercase tracking | eyebrow tell | condensed 700 at normal case; uppercase only on stamps |
| Sheet header with a tinted gradient | wash | flat `--sub` with a 2 px bottom edge (the original's modal header) |

Result: the only novel objects are the slip and the ignition; the rest is the original's tactile identity made consistent, with more type discipline and fewer decorative effects. Deliberately **not** done: scroll reveals, hover lifts on every card, backdrop blur (cost on tablets, and the original's one needless effect), icon-in-circle decorations.

## 4. Contract additions (beyond SPEC section 19)

Everything in SPEC 19 exists with the signatures given there. Extensions (all additive):

**SB.ui**
- `sheet(opts)` also takes `name, opener, closeOnBackdrop, closeOnEsc, initialFocus, restoreFocus, role:'alertdialog', closeLabel`; it returns `{el, root, body, header, footer, titleEl, name, close(reason), isOpen(), setTitle(t), focus(elOrSelector)}`. Esc, backdrop, the sheet's own X and browser Back all close it; focus returns to the opener; the layers behind are `inert`.
- `toast(msg, {tone, undo, ms})` returns `{el, close()}`. One undo toast at a time, at most 3 toasts, the bar drains over `SB.config.undoMs` (10 s default) and pauses while hovered or focused.
- `stepper` adds `bigStep` (extra -N/+N buttons), `unit`, and methods `getValue/setValue(v,{silent})/setRange(min,max)/destroy`, property `.input`. It never emits NaN, Infinity or 1e+30.
- `segmented` adds `kind:'tabs'`, option fields `count/alert/alertLabel/ariaLabel`, and `getValue/setValue/setOptions/setCount(id,n,{alert})`.
- New: `toggle`, `meter`, `field`, `errorCard`, `copyText`, `closeMenu`, `badgeWords`, `chip({mod,zone,onClick,pressed})`.
- Badge words are fixed: ok "On time", warn "Running late", breach "Overdue" (word + icon + colour).

**SB.sheets** `has(name) names() isOpen(name) top() count()` besides `register/open/closeAll`. Opening a name that is not registered shows a toast, never throws; opening an open name focuses it.

**SB.router** `zones`, `sections`, `lastZone()`, `index()`, `init()/destroy()`, `leaveOffice()`, `overlay.push/release/depth`. `view(hash)` is `viewFor`, `hash(view)` is `hashFor`; both total. Rules: a sheet owns one history entry while open; closing it with its own button, Esc or the footer steps back (`history.back()`), browser Back closes it; the same view is never pushed twice; the office is one pushed entry and "Back to the line" steps back to where you were (or replaces if it was a pasted link). A view change queued behind a traversal wins over what the URL still says (the PIN keypad closes, then the office opens).

**SB.theme** `toggle()`, `onChange(fn(what, state)) -> off`. Storage keys: `smokebox.v1.theme`, `.otheme`, `.textsize`, `.zone`, `.pinlock`. The theme is *not* mirrored into `state.settings`.

**SB.shell** `brand({text,size})` (the `[data-brand]` button every floor header must use), `mount/unmount`, `isMounted`, `promptPin`, `hasPin`, `hashPin`, `checkPin`, `setPin(pin|null)`, `lock`, `sha256`, `GRACE_MS`. The PIN hash lives at `state.settings.office.pinHash` (read with `SB.store.getState()`, written with `SB.store.dispatch('updateSettings', {patch:{office:{pinHash}}})`). Attribute `[data-back-to-line]` on any button leaves the office. SB.office is mounted at each ignition and unmounted after each close, so a page that keeps timers must clean up in `destroy`.

**CSS names (the floor and office agents may use these)**
- Tokens: `--primary --on-primary --primary-edge --success --on-success --danger --on-danger --hover --press --inv-bg --inv-ink --inv-ink2 --inv-line --inv-accent --inv-ok --inv-warn --inv-bad --focus-inv --slip --slip-ink --slip-sub --slip-rule --slip-line --zp-pit.. --zi-* (z-index) --fs-1..8 --fs-ticket --fs-timer --fs-item --sp-1..10 --tap --tap-lg --tap-step --r-slip --r-chip --r-field --r-btn --r-panel --r-dialog --bw --bw-focus --measure`. Inside `.office` the floor names are remapped to `--o-*`; inside `.slip` they are remapped to the paper palette, so any button, chip, stamp or meter placed on a slip is legible in Night.
- Slip kit: `.slip[data-level=ok|warn|breach] > .slip-clip + .slip-head + .slip-body + .slip-tear`; inside: `.slip-id .slip-num .slip-who .slip-meta .slip-time .slip-timer[data-level] .slip-progress>i[--v] .slip-note .slip-item[data-state] .slip-qty .slip-name .slip-mods .slip-foot`; `.is-printing` plays the print-in. A `.stamp` placed in `.slip-head` sits right, half over the progress bar.
- Controls: `.btn` (+ `-primary -success -danger -ghost -lg -sm -icon -block`), `.chip` (`-mod -zone`, `[data-zone]`), `.badge[data-level]`, `.seg .seg-opt .seg-count .seg-dot`, `.stepper*`, `.field .input .select .textarea`, `.toggle`, `.meter[data-tone][--v][--thr]`, `.panel .panel-soft .well .divider .kbd .empty`, `.stamp(.stamp-lg)`, `.visually-hidden`, `.text-large`, `.t-muted`, `.row .stack`.
- Layers: `#sb-floor`, `#sb-office` (class `office`, `data-otheme`), `.sb-shell[data-view]`, `.layer`, `.ignite-veil`, `.ignite-fx`, `.ember-ring`, `.wisp`.

**Known compositing trap.** While the office clip-path circle animates, `.layer-office` gets `will-change: clip-path` (class `is-igniting`/`is-snuffing`). Without it Chromium with software raster left undimmed and black patches outside the circle. Do not remove it.

## 6. The walkthrough ("Practice run (2 minutes)")

Why: a first-time owner opened the board, saw five overdue tickets and could not tell what the app was for. The fix is a guided loop on one fresh ticket instead of a manual.

- **What it is.** `SB.tour` (`src/js/74-floor-tour.js`, styles in `src/css/22-floor-tour.css`). `SB.tour.start()` adds one Walk-up ticket (hush puppies, brisket sandwich, sweet tea) and shows a dark caption card with a pulsing amber ring on what to tap. `SB.tour.stop()` ends it; `SB.tour.active()` (alias `running()`) says whether it is on. Starting again while one runs begins again at step 1 with a new ticket; the old tour ticket stays on the board.
- **Nine steps:** ticket, clock, stations (tap START on the hush puppies), cook timer, gray dishes, start the sandwich, tap done, Bump, the whole loop. Steps 1, 2, 4 and 5 have a Next button because there is nothing to tap; the others wait for the real ticket to change.
- **It follows the ticket, not a script.** Every 250 ms it reads the ticket and moves forward only (never back). Doing things in another order skips the steps already done: starting the hush puppies at step 1 lands on step 4 (or 7 if the sandwich is already cooking); finishing every dish lands on step 8; bumping early (even with "Bump anyway") lands on step 9. A voided or removed ticket ends the tour.
- **Clock.** The 30x clock starts at step 5, not earlier: the pacing offsets are measured from when the ticket arrived, so a fast clock earlier would run the gray countdown out before the person had read about it. Step 5 also holds for 5 real seconds. The old speed is put back at step 9, on Skip, on Escape, or when the ticket disappears. If the person changed the speed in the meantime it is left alone.
- **Never covers what it points at.** On a wide screen the card sits in the free space beside the ticket (right first, then left), level with the first ring. On a phone, or when there is no room, it docks at the bottom or the top of the screen; if neither end is clear the board is nudged for the first two seconds of a step. It hides while any sheet (`.sheet-root`, which includes confirm dialogs) or the back office is open and returns at the same step. Escape ends the tour unless a sheet is open, when Escape belongs to the sheet.
- **Selectors it depends on:** `.fl-slip[data-ticket]`, `.slip-head`, `.slip-next` (optional), `.slip-timer`, `.fl-bw`, `.fl-row[data-menu][data-state][data-kind]`, `.fl-bump`, `.fl-new`, `.fl-start-demo` (optional), `.fl-seg [data-id="all"]`, the header Demo button, `#fl-board`, `.sheet-root`. The ring is an inset outline because `.slip-time` and `.slip-id` are `display: contents` and cannot carry one.
- **Test.** `test/e2e/13-tour.mjs`: the full loop with real clicks, Skip and Escape cleanup, out-of-order play, pausing for a sheet and the office, and layout checks (card on screen, no ring covered, every ring visible, Bump free, buttons 44 px) at 1280x800, a 390x844 phone, Large text and a busy board. `node tools/qa.mjs --only tour` runs it with the rest of the suite.

## 7. Plain words, compact tickets and the first screen

Why: the same owner said the app was "not intuitive" and "crowded". These are the rules that came out of it.

- **Words a cook already uses.** A dish that is held back says `Start in 2:08` and has a `Start now` button. A dish that is ready says START (two-step) or DONE (one-step). Nothing on screen says "fire" or "on deck" any more (the internal names `fireNow`, `data-act="fire"` and `queued` are unchanged).
- **Start now is one tap.** The engine's `fireNow` takes `start:true`: a two-step dish goes straight to cooking (marked override, so it is not used for learning), a one-step dish just moves to the screen. Undo puts it back to waiting.
- **The "do this next" line.** `.slip-next`, under the header, built by `nextFor` in `70-floor-board.js` from the ticket's own items. Priority: Check it, then START, then make-and-DONE, then time left, and the soonest waiting dish is added at the end. When everything is done it says "Everything is done. Tap Bump." It is written only when its words change and never adds a node in the 1 Hz tick (F-O1). A Settings switch (`SB.theme.hints`, saved) hides it.
- **The cook countdown.** Under the dish name, in the place a waiting dish shows its start time: `4:59 left`, then `Check it +0:42` at zero. The row and tile flash (not when motion is reduced), Check it is spoken once, and a three-beep chime plays only when Sound is on. It is only a cue: nothing marks the dish done by itself, because the app cannot see the fryer.
- **First screen.** Three fresh tickets (25, 12 and 3 seconds old, no rush, so pacing shows) and a welcome card with "Practice run (2 minutes)" and "Start with an empty board". The card is not a modal, so the board stays usable behind it. It shows on the All tab only, offers to clear the board only when every ticket is a demo ticket, and is dismissed for good with the x. "Restart demo" in the Demo sheet clears the board, puts the clock back to real time and brings the card back. Nothing runs by itself unless the busy-night demo is started.
- **Compact tickets.** `paintDensity` sets `data-density` on the board from the ticket count against `fullCols()`; Settings has Auto, Full size and Compact. Full-size tickets are untouched. In compact the short menu name is shown and the full name stays in the reading order for screen readers.


## Back office is a visible button (design change)
